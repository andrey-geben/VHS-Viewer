О программе

VHS-Viewer — веб-клиент и событийный концентратор для VHS-Streamer. Показывает камеры в мозаике через WebRTC, принимает события аналитики и связывает их с внешними управляемыми устройствами.

Что умеет

Мозаика и WebRTC

Потоки 16:9, раскладки 1×1…4×4, поиск, полноэкранный режим, автоматическое переподключение. Можно подключить несколько VHS-Streamer — у каждого свой URL и ключ.

просмотр

События и снимки

Журнал событий с фильтрацией по камере, категории, номеру и времени. Снимки хранятся рядом с событиями и доступны из карточки.

events / snapshots

Аналитика

Детекция объектов YOLO и распознавание номеров (ALPR). Для каждой камеры отдельно задаются объекты, номера и частота анализа.

YOLO · ALPR

HTTP-реле

Открытие внешнего устройства по распознанному номеру: шлагбаум, замок, ворота, сирена, свет. GET/POST, закрытие по таймеру.

plate → relay

Уведомления

Telegram, MAX и webhook. Фильтры по категории, камере и уверенности; шаблон сообщения, снимок, cooldown от спама.

Telegram · MAX · webhook

Боты и API

Боты VK/MAX/Telegram/WhatsApp с белым списком пользователей и командой открытия реле. API Viewer используется VHS-Security.

bots · integration

Связка модулей VHS

Viewer — центральный узел между видео и охраной. Он принимает потоки от одного или нескольких Streamer и отдаёт камеры/события в Security. Все внутренние запросы подписываются заголовком X-VHS-Key (совместимо с X-API-Token и X-Ingest-Token).

МодульЧто настроитьКлюч
VHS-Streamer Настройки → Безопасность → «Ключ интеграции». Добавить камеры и включить потоки. X-VHS-Key
VHS-Viewer Настройки → «Серверы VHS-Streamer»: имя, URL, ключ. Затем «Обновить список потоков». ключ каждого Streamer
VHS-Viewer Настройки → «Внутренний API и ключи»: ключ Viewer для Security. X-VHS-Key
VHS-Security Настройки → «Интеграция VHS»: Viewer URL и ключ Viewer; при необходимости Streamer URL и ключ. X-VHS-Key
Несколько Streamer. В настройках Viewer можно добавить любое количество серверов; у каждого свой URL и ключ. Потоки агрегируются, а в имени появляется префикс сервера:

servers:
  - name: Объект-1 · url: http://192.168.1.10:8100 · api_key: ...
  - name: Объект-2 · url: http://192.168.1.11:8100 · api_key: ...

Варианты взаимодействия

КаналЧто делаетКогда срабатывает
HTTP-реле GET/POST на url_open; при заданном url_close — закрытие через N секунд. Заголовки, Basic Auth, таймаут. Только распознанный номер из белого списка, с выбранных камер, с учётом cooldown.
Webhook POST/GET с JSON {text, event} на URL внешней системы. Любое событие аналитики, подходящее под фильтры канала.
Telegram / MAX Текст и снимок события в чат или канал. Любое событие аналитики по фильтрам категории/камеры/confidence.
Бот Команда от пользователя из allowed_user_ids открывает выбранное реле. Ручное управление; не зависит от детекции.
Integration API /api/integration/state и /api/integration/events с X-Ingest-Token. VHS-Security и другие внешние системы читают камеры, события и снимки.

Что можно подключить

Любое устройство с HTTP-управлением: контроллер шлагбаума или ворот, умное реле, электромагнитный замок, сирена, свет, контроллер доступа, Home Assistant, промышленный шлюз или промежуточный webhook. Viewer не коммутирует 220 В напрямую — нужен внешний контроллер или реле.

Важно: автоматическое открытие по номеру работает только для событий категории plate. Детекция людей, машин и объектов используется в журнале и уведомлениях; для управления реле по ним нужен отдельный webhook-сценарий на стороне внешней системы.

Безопасность

  • Роли admin и viewer; настройки и реле доступны администратору.
  • CSRF-защита форм и API; сессионная авторизация; отдельный ingest-токен для Security.
  • Белый список пользователей ботов и белый список номеров для реле.
  • Cooldown на реле и уведомления, чтобы событие не открывало устройство повторно.
  • Viewer не публикует порты в интернет; доступ — через локальную сеть или WireGuard.
