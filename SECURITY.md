# Безопасность VHS-Viewer

Документ описывает результаты проверки кода и рекомендации по безопасной эксплуатации.
VHS-Viewer — локальный клиент просмотра, но по умолчанию слушает `0.0.0.0:8200`,
поэтому его сетевая экспозиция важна.

## Что уже исправлено

- **Жёстко заданный `secret_key`** (`vhs-viewer-secret-change-me`) заменён:
  ключ берётся из `VIEWER_SECRET` или генерируется случайным и сохраняется в
  `logs/.session_secret` (права `0600`).
- **Пароль администратора по умолчанию** (`admin` / `viewer`) удалён из
  `DEFAULT_CONFIG`: пользователи создаются только мастером первого запуска.
- **Open redirect** в `/login?next=...` — разрешены только локальные пути.
- **Cookie сессии**: `HttpOnly`, `SameSite=Lax`, `Secure` при `VIEWER_HTTPS=1`.
- **Ограничение попыток входа**: 10 неудачных попыток с одного IP за 10 минут.
- **Защитные заголовки**: `X-Content-Type-Options`, `X-Frame-Options`,
  `Referrer-Policy`, `Permissions-Policy`.

## Что осталось и требует решения

1. **Пароли хранятся в открытом виде** в `viewer_config.yaml`, а
   `GET /api/security/config` возвращает их администратору в открытом виде.
   Рекомендация: перейти на `werkzeug.security.generate_password_hash`,
   отдавать в UI только признак «пароль задан» и менять его отдельным полем.
2. **Нет CSRF-токенов** на state-changing POST-запросах. JSON-эндпоинты
   (`request.get_json`) и `SameSite=Lax` снижают риск, но для полной защиты
   нужен CSRF-токен (например, Flask-WTF) или проверка `Origin`.
3. **Мастер первого запуска `/setup` доступен без авторизации** до записи
   `_setup_complete: true`. Если сервис впервые поднят на `0.0.0.0`, любой в сети
   может завершить настройку и стать администратором. Рекомендация: слушать
   `127.0.0.1` до завершения setup или требовать одноразовый токен из консоли.
4. **Нет HTTPS из коробки** — `viewer.py` запускает HTTP. Для доступа не с
   localhost ставьте reverse-proxy с TLS и включайте `VIEWER_HTTPS=1`.
5. **SSRF через админские функции**: URL серверов VHS-Streamer, webhook-каналы
   уведомлений и реле — администратор может указать внутренний адрес. Ограничьте
   доступ к админке и проверяйте allowlist на сетевом уровне.
6. **Секреты реле/ботов** (`RELAY_SECRET`, `BOT_CONFIG_SECRET`) хранятся в `.env`;
   сравнение токенов не constant-time (`!=`). Секреты длинные и случайные, но
   лучше использовать `hmac.compare_digest`.
7. **Нет CSP**: шаблоны содержат inline-скрипты, поэтому строгий CSP потребует
   выноса JS в файлы. Как минимум можно добавить `frame-ancestors 'self'`.
8. **Роли упрощены**: `viewer` не имеет доступа к админ-страницам, но все
   API проверяют только `admin`; при доработке стоит покрыть тестами каждый
   эндпоинт на роль.

## Рекомендации по развёртыванию

- Слушайте `127.0.0.1`, если клиент нужен только на этом компьютере.
- Для удалённого доступа — reverse-proxy (nginx/Caddy) с TLS, `VIEWER_HTTPS=1`.
- Задайте `VIEWER_SECRET` (32+ символа) и храните `.env` с правами только владельца.
- Ограничьте доступ к `/setup` и админ-страницам по IP/VPN.
- Регулярно проверяйте `logs/` и обновляйте зависимости (`pip list --outdated`).
